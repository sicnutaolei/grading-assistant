# 阅卷助手 · 化学第16题

在网页阅卷系统里加一个按钮：识别答题卡手写内容 → 按内置细则逐条判分 → 点击分值按钮。

> **重要：光大阅卷系统里"点击分值按钮"本身就是提交。** 工具从不点击"提交分数"按钮，
> 但点 0~14（语文是 0~4）的分值按钮会直接落库并跳到下一份。默认需要你手动点一次"提交分值"，
> 自动提交是设置里的独立开关，见下。

识别后端：**DeepSeek `deepseek-flash`**（原生多模态，OpenAI 兼容接口）。

- `extension/` —— Chrome 扩展（MV3，加载已解压的扩展程序即可）
- `cli/grade.mjs` —— 命令行自检：本地图片直接跑一遍判分链路，用来验证细则和识别质量
- `fixtures/answer-226-1-1.png` —— 样例答题卡（密号 226-1-1），期望总分 **4 / 14**
- `extension/platform.js` —— 平台自适应探测（卷面 canvas/img、分值按钮、当前得分、密号）
- `extension/rubric-core.js` —— 细则引擎（生成提示词、解析校验判分结果）
- `extension/rubric-chem-q16.js` —— 化学第16题（14分，7 个空）
- `extension/rubric-q19.js` —— 化学第19题（13分，有机；第4、6小问按结构式判分，附标准结构图）
- `extension/assets/` —— 内置细则引用的参考结构图
- `extension/rubric-yw-translate.js` —— 语文文言文翻译（4分，4 个给分点）
- `extension/rubrics.js` —— 细则注册表，面板/设置页下拉切换；再加一题只需多写一个细则文件
- `extension/llm.js` —— 视觉判分客户端（改 base url 就能接任何 OpenAI 兼容接口）
- `tests/smoke.mjs` —— 面板冒烟测试（jsdom 里跑装配 -> 判分 -> 填分，含"绝不点提交"断言）

## 三、已验证结果（2026-10-14）

**语文 · 文言文翻译**（原句"一旦水旱荐至，何以救命之困"）：真实手写样本 3/4（"荐"漏译扣分、"用什么来"给分）与人工判分一致；
另用楷体渲染 5 份译文验证采分点区分度——全对 4/4、"荐"错译"推荐" 3/4、"何以"译成"为什么" 3/4、"困"译成"疲倦" 3/4、大面积漏译 0/4，全部符合预期。
过程中修掉一个重复扣分问题：个别词错译原本会同时打掉该词和"句意"两点，现已限定句意分只看整句大意。

**化学 · 第16题**：样例卷 4/14 连跑 4 次一致；阅卷页真实卷面 5/14 与人工读卷逐空一致。

样例卷连跑 4 次，总分 4/14 **4/4 一致**，逐空判分与人工读卷完全相同；单次 5~9 秒，
输入约 2042 tokens、输出约 950~2000 tokens。按 DeepSeek 公开报价（输入 1 元/百万、输出 4 元/百万）
估算 **一份约 0.006~0.01 元，85 份不到 1 元**；报价来自第三方整理，正式使用前以控制台实时价为准。

模型带思维链，偶尔会把输出预算用尽导致 JSON 被截断，客户端已做两件事：截断或缺空时自动加大预算重试；
**只要 7 个空没有全部返回就判定失败**，不会把缺失的空按 0 分悄悄算进总分。

## 五、平台自适应

面板第二行会实时显示探测结果，例如：

```
平台：画布×4｜分值 0–14（15个）｜得分 0｜密号 1713-1-3
```

探测逻辑（`extension/platform.js`）：

| 目标 | 策略 |
| --- | --- |
| 卷面 | 优先取有墨迹的同源 `canvas`（多图层按顺序合成后裁到墨迹范围）；没有则取面积最大的 `<img>` |
| 分值按钮 | 先试 `ul.scores li` / `.level-item` / `[class*=score] li` 等常见结构；都没有就找"成组的连续数字叶子节点" |
| 当前得分 | 找文本形如 `得分：N` 的最内层元素 |
| 密号 | 依次匹配 `密号：xxx`、`试卷号：xxx`；没有密号的系统退回用"已批阅量"标识卷面 |
| 提交按钮 | 找文本为 `提交分数`/`提交`/`保存` 的按钮；点分值不落库的平台，自动提交时点它 |

已实测的两家：

- **光大阅卷**（`/njs_3335/#/painter`）：4 层同源 canvas；`ul.scores li` 0~14；点分值即提交并翻页；无独立提交按钮。
- **学科网 e卷通**（`yuejuan.xkw.com`）：canvas 被跨域污染、`getImageData` 抛 SecurityError，自动退回**截屏裁剪**取图；
  `.key-numbers span` 0~13；分数写在 `.ques-score` 的 input 里；有独立"提交分数"按钮，点分值只填不落库。

换一家阅卷系统时先看这行——四项都认出来了就能直接用；认错了把面板上的这行文字发我，加一条选择器即可。

## 六、自定义细则（不用改代码）

设置页底部是 JSON 编辑器：新增/修改任意题目，保存前会校验结构（id 唯一、每个给分点有 label/max/answer），
保存后刷新阅卷页即可在面板下拉里选到。结构式题在条目里加 `"type":"structure"`，
再在"参考结构图"里上传标准结构，把得到的 key 填进 `"standardImage"`——判分时会把标准图和学生卷面一起交给模型做视觉比对。

实地核对过，选择器写死在 `content.js` 里：

| 目标 | 实际结构 |
| --- | --- |
| 卷面 | 4 层 `canvas`（1920x844，同源未污染），**没有 `img` 元素**，靠合成 + 墨迹裁剪取图 |
| 分值按钮 | `ul.scores > li.f-csp`，文本 0~14，共 15 个 |
| 当前得分 | `div.fs` 内 `label`，文本形如 `得分：0` |
| 提交按钮 | `span.submit-btn`，文本"提交分数"，扩展只识别它、永不点击 |
| 密号 | 顶栏文本 `密号：300-1-1`，用于本机判分记录 |

## 七、日常用法

| 操作 | 方式 |
| --- | --- |
| 识别并判分 | 面板按钮或 `Alt+1` |
| 提交分值（本系统即提交） | 面板按钮或 `Alt+2` |
| 取消自动提交 | 倒计时条上的"取消"或按 `Esc` |
| 换图片 | 面板下拉框 / "刷新" |
| 页面图片取不到 | "粘贴截图" 后 `Ctrl+V` |

## 八、自动提交（默认关闭）

设置页四项目：

| 开关 | 默认 | 作用 |
| --- | --- | --- |
| 自动提交 | 关闭 | 判分完成后自动点分值（=提交） |
| 提交前倒计时 | 3 秒 | 期间可点"取消"或按 Esc；填 0 = 立即提交 |
| 置信度下限 | 0.6 | 低于此值不自动提交，只提示人工核对 |
| 连续模式 | 关闭 | 提交翻页后自动开始判下一份 |

建议第一次打开时把倒计时调到 8 秒，先跑一份中途按取消确认能停，再按需要缩短。

## 九、安全边界

- 密钥只存在本机 `chrome.storage.local`（或 `secrets/deepseek.key`），不写进代码文件，不进 git。
- 只有你点按钮时才会把答题卡图片发给 DeepSeek 接口。
- 只允许点击文本为分值的数字按钮；含"提交/保存/确认/上一份/下一份/回评"的元素一律拒绝点击。
- 点击前四道校验，任一不过就停手报警：卷面密号与判分时一致（防止把上一份的分判给下一份）、
  分值按钮存在且唯一、判分解析出全部条目、置信度不低于阈值。
- 点击后轮询 6 秒确认结果：密号变了 = 已提交并翻页；得分等于判分值 = 已填分未翻页；都没有 = 报警请人工核对。
- 判分结果只是辅助，**提交前请人工核对**，尤其是置信度偏低或识别文字与卷面不符时。
